# EaglEs EyE Roadmap

## Delivery protocol

Only one phase may be active at a time. Complete the active phase, verify its
acceptance criteria and tests, update `ARCHITECTURE.md`, `PROJECT_STATUS.md`,
`NEXT_TASK.md`, and `AI_TWIN_CONSTITUTION.md`, then stop and wait for the next
phase.

## Phase 8 — AI Twin Observer Foundation

**Mission:** Observe complete AI coding sessions.

### Deliverables

- `WorkspaceObserverService`
- `ExecutionTimelineService`
- `SessionRecorderService`
- `TwinBuilderService`
- `ReplayService`
- `AgentDetectorService`
- Multi-workspace support
- Local Twin directory
- Timeline reconstruction

### Acceptance

> “Replay everything the AI did yesterday.”

## Phase 9 — Multi-Agent Observation

Watch multiple coding agents simultaneously.

### Supported agents

- Codex
- Claude Code
- Gemini CLI
- OpenCode
- Aider
- Cursor
- Cline
- Roo Code
- Windsurf
- GitHub Copilot
- Future MCP agents

### Features

- Session comparison
- Agent comparison
- Timeline comparison
- Performance comparison
- Architecture comparison

### Acceptance

> “Compare Codex vs Claude implementing the same feature.”

## Phase 10 — Cognitive Layer

This is evidence-based engineering reasoning, not hidden reasoning.

### Examples

- Why did this service change?
- Which file caused later edits?
- What sequence produced this architecture?

### Features

- Engineering reasoning graph
- Causal graph
- Reflection engine
- Architecture evolution
- Knowledge freshness
- Decision tracking
- Evidence-backed explanations

### Acceptance

> “Explain why `RetrievalService` changed.”

## Phase 11 — MCP Ecosystem

Become an MCP-native observer.

### Features

- MCP Server
- MCP Tool Registry
- External integrations
- IDE support
- Remote observers (optional)
- Plugin SDK

### Acceptance

Any MCP-compatible AI can query EaglEs EyE.
